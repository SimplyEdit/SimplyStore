# Schema objects lose identity across the query isolate

Observed on master bd61d9c with curriculum-store's 92 KB `schema.jsontag`.
A query for `meta.schema` fails in both JSON and JSONTag modes. With default
limits it exhausted the 64 MiB isolate heap after about 2.5 s; the maintainer
observed the 10 s slow-query timeout. Smaller contexts succeed, but their
JSONTag responses expand shared objects instead of linking them: the
`kerndoelen` context returns 28,227 bytes where host serialization returns
6,957.

The schema is acyclic. It contains 281 distinct objects and 734 shared
references. Treating every path as a distinct object expands it to 99,001
objects. Host-side, the whole schema serializes to 49,844 bytes of JSONTag in
about 1 ms (4,012,890 bytes of JSON).

Cause: DES-20260924-TTZ7C-59 identifies query objects by "record numbers plus
property paths (or schema paths)". A record number is a stable identity, and
od-jsontag stores every data object as its own record, so data arrays have one
owning path. Schema objects are ordinary JSONTag objects that may be reached
by many paths. The guest caches proxies by reference, so one schema object
becomes a distinct proxy per path: `===` fails, the JSONTag serializer cannot
emit links, and each path repeats its host reads.

Earliest meaningful cause: the design assumed path uniqueness for schema
objects. Verification did not catch it because the query test schema is a
tree. The correction belongs in the design's identity rule, followed by the
implementation and a regression with a shared/cyclic schema.
