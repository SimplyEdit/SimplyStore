# Verification Evidence: Durable Artifact Corruption Classification

## Claim being verified

`IMP-001` now classifies malformed and structurally invalid command-status and command-log startup records as explicit recovery integrity failures.

## Why this evidence exists

`DES-001` requires detectable corruption. `CYC-004` proved shared durable startup parsing, but malformed/truncated records remained an unclassified gap.

```text

```

Results:

- `npm test` passes: 19 assertions pass, 1 existing empty test file remains skipped.
- Targeted ESLint passes.

The new tests cover:

- malformed durable command-status line;
- command-status record missing required `command` field;
- malformed durable command-log line;
- command-log record missing required `id` field.

Each case raises `RecoveryIntegrityError` with file, line number, and record kind metadata.

## Failure cases / limits

- This does not prove full process restart behavior.
- This does not inject crashes.
- This does not classify every possible cross-file inconsistency.
- This does not repair unawaited durable append calls.
- This does not introduce integrity hashing.

## Evidence quality

This evidence directly exercises the shared recovery helpers used by server startup and makes a narrow D6 detectable-corruption slice executable. It improves developer evaluation confidence for malformed durable status/log records without making broader production-safety claims.
