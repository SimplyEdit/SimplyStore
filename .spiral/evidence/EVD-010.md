# Verification Evidence: ACID Non-Durability Baseline

## Claim being verified

`IMP-005` adds smoke-level executable evidence for SimplyStore's Atomicity, Isolation, narrow Consistency, and duplicate command ID idempotency claims.

## Why this evidence exists

SimplyStore's production-readiness work has focused on durability, but the project publicly frames its command/query design using ACID language. A skeptical developer should see at least baseline evidence for the other letters before deeper durability work continues.

## Result

Commands run:

```text
npm test
npm run test:acid
npm run test:durability
npx eslint test/acid-baseline.mjs test/durability-helpers.mjs
git diff --check
```

Results:

- `npm test` passes with 10 startup/unit durability tests.
- `npm run test:acid` passes with 4 server-level ACID baseline tests.
- `npm run test:durability` passes with 13 process durability tests.
- Targeted ESLint passes.
- `git diff --check` passes.

The ACID baseline tests cover:

- a failed command that mutates before throwing does not become visible or committed;
- a query mutation attempt is rejected with `422` and does not affect later queries;
- a query during an active command sees the previous committed state;
- after command completion, queries and the reconstruction oracle see the committed new state;
- duplicate command IDs do not apply twice and remain single-application after restart.

## Failure cases / limits

- This is smoke-level evidence, not a complete ACID proof.
- Domain consistency is intentionally out of scope.
- The duplicate command ID response body may be confusing even though the state behavior is idempotent.
- These tests start servers and are intentionally separate from `npm test`.

## Evidence quality

The evidence is sufficient to support a developer-facing baseline statement that SimplyStore has executable smoke coverage for non-durability ACID claims. Durability remains the deeper, higher-risk proof area.
