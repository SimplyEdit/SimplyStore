# Verification Evidence: Malformed OD-JSONTag Record Framing Classification

## Claim being verified

`IMP-006` refuses malformed or truncated OD-JSONTag record framing in base data and committed changeset files during startup reconstruction, while safely ignoring uncommitted changesets with malformed framing.

## Why this evidence exists

The human was especially worried about corrupted or altered OD-JSONTag files. OD-JSONTag files are the actual durable state material, so malformed committed record framing must not silently become valid recovered state.

The new/expanded startup tests cover:

- base OD-JSONTag file with malformed record framing refuses recovery;
- committed changeset with malformed record framing refuses recovery;
- truncated committed changeset payload refuses recovery before lazy parsing can hide it;
- uncommitted changeset with malformed record framing is ignored during committed startup reconstruction;
- direct framing validation catches truncated lazy records;
- direct framing validation accepts valid changeset skip records.

## Failure cases / limits

- Well-formed malicious changeset alteration cannot be detected with the current durable format.
- The validator checks OD-JSONTag record framing, not full OD-JSONTag syntax, command identity, hashes, signatures, or semantic correctness.
- Cleanup/reset/repair tooling remains future work.

## Evidence quality

This evidence is strong for malformed/truncated OD-JSONTag record-framing classification. It deliberately does not overclaim full syntax validation or tamper detection for well-formed altered files; that requires future integrity metadata.
