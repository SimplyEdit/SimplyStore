# Verification Evidence: Malformed OD-JSONTag Storage Classification

## Claim being verified

`IMP-006` refuses malformed or truncated OD-JSONTag base data and committed changeset files during startup reconstruction, while safely ignoring malformed uncommitted changesets.

## Why this evidence exists

The human was especially worried about corrupted or altered OD-JSONTag files. OD-JSONTag files are the actual durable state material, so malformed committed data must not silently become valid recovered state.

The new/expanded startup tests cover:

- malformed base OD-JSONTag file refuses recovery;
- malformed committed changeset refuses recovery;
- truncated committed changeset payload refuses recovery before lazy parsing can hide it;
- malformed uncommitted changeset is ignored during committed startup reconstruction;
- direct framing validation catches truncated lazy records;
- direct framing validation accepts valid changeset skip records.

## Failure cases / limits

- Well-formed malicious changeset alteration cannot be detected with the current durable format.
- The validator checks OD-JSONTag framing, not command identity, hashes, signatures, or semantic correctness.
- Cleanup/reset/repair tooling remains future work.

## Evidence quality

This evidence is strong for malformed/truncated OD-JSONTag storage classification. It deliberately does not overclaim tamper detection for well-formed altered files; that requires future integrity metadata.
