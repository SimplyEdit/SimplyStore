# Evidence: Command And Conversion Offset Finalization

Verified on 2026-09-17 with Node v24.7.0.

## Regression Evidence

All six command-offset tests failed before implementation. They exposed offsets
into the prior file, missing appended entities and hook-introduced mutations,
incorrect successive changesets, stale no-op indexes, and a missing failure
when the final sidecar could not be written.

After implementation, all 53 tests passed:

- `npm test`: 28 startup, conversion, and command-offset tests.
- `npm run test:handlers`: 4 tests, including final offset-write failure causing
  failed status with the previous committed state visible and reconstructable.
- `npm run test:acid`: 5 atomicity, consistency, isolation, and retry tests.
- `npm run test:durability`: 16 tests including crash boundaries, restart,
  timeouts, retry safety, and integrity-enabled command completion.

Offsets are checked against an independent disk-byte framing oracle, including
UTF-8 text, leading and interior skips, newly allocated records, hook mutations,
successive changeset files, and empty changesets. Replaying base plus changesets
preserves the expected logical data.

The shared writer was also run against the local downstream 181,724-record base
file with output confined to a temporary directory. Every offset matched the
independent byte scan. Writer plus verification took 0.230 seconds in this one
local run. The temporary output was removed; downstream files were not written.

Scoped ESLint checks on command-offset tests, handler tests, and recovery code
passed. Staged Spiral validation and whitespace checks passed before the
implementation commit. Tests requiring processes/sockets ran with sandbox
escalation; provenance validation used the existing temporary Python environment
with rdflib.

## Limits

Existing stale sidecars are not repaired automatically. The corrected package
has not been released or installed in curriculum-store. The final writer makes
successful commands await complete offsets; it does not make the changeset,
offset sidecar, and integrity record one atomic filesystem transaction. Failed
or interrupted commands may leave uncommitted derived files, which the existing
status-driven recovery excludes. Human acceptance remains pending.
