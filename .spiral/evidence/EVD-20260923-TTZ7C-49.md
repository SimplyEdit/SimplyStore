## Final read-failure correction

DEF-20260923-TTZ7C-50 records two failing regressions introduced during final
review. Late lazy reads could be treated as ordinary command errors or swallowed
inside query code. FileParser now records read/decode/reference failure in
host-owned session state. Commands refuse publication even when a handler catches
the failure; query workers signal it to the runtime even when query code catches
it. Forged user-thrown storageFailure properties do not change that state.
The runtime stops mutation and retains ownership/recovery evidence.

The complete suite passes 142 tests after that correction (faa3e89). The final
response-format refinement (cdc1564) additionally passes all 23 focused file-data
tests, including JSONTag error negotiation. Focused lint remains clean. Earlier
memory, curriculum and package probes establish the unchanged file-source and
distribution contracts; they are not separate security or hardware claims.

## Boundaries and review disposition

Startup hashes all canonical bytes and validates persisted IDs from record
headers, with reconstruction as fallback. Index catalogs remain O(records), handles O(source files per worker),
and mutable sessions retain touched data. Command output/custom hooks/query
results may be large. Schemas and logs remain in memory; administrative copying
still temporarily buffers individual files. These are documented boundaries,
not a constant-memory claim. The large-file result does not establish a broader
filesystem or hardware durability envelope; the separate QEMU power-cut campaign
was not repeated.

Internal custom worker implementations must use the new source contract;
`inspectStore` returns `sources` instead of live `data`/`buffers`. Existing custom
index finalizers retain their call contract. Source files must be immutable
while open under store ownership. A Git dependency pin is used until a separate
od-jsontag npm release. Client version metadata/audit history and query sandbox
selection remain later work.
