# Verification Evidence: First Startup Recovery Harness

## Claim being verified

The first executable durability harness checks whether startup/recovery treats command-status/changeset mismatches according to the intended durability invariants:

- an accepted but not completed command must not become visible as committed state;
- a completed command whose changeset is missing must fail recovery explicitly rather than silently using an earlier state.

## Why this evidence exists

`CYC-002` targets the sharpest contradictions from `EVD-001` before broader crash injection. This evidence preserves current failing behavior as regression tests.

## Result

Command run:

```text
npx tap test/durability-startup.mjs
```

Result: failed, as expected for the current implementation.

Full project test command also run:

```text
npm test
```

Result: failed with the same two durability failures. Existing `test/produce.mjs` remains skipped because it contains no active tests.

Observed counterexamples:

1. `accepted-command` with an existing changeset file becomes visible after startup. The restarted data contains `persons[0].name == "Ada"` even though the simulated command is only accepted, not done.
2. `done-command-with-missing-changeset` does not reject recovery. The load worker resolves successfully instead of producing a missing-changeset or inconsistent-state error.

These failures preserve two current gaps against `DES-001`:

- D1 committed-state recovery;
- D2 no partial command visibility;
- D6 detectable corruption.

## Failure cases / limits

- The harness currently exercises `src/load-worker.mjs` directly rather than starting the full HTTP server.
- The harness simulates status selection by passing command IDs to the loader; it does not yet parse command-status files itself.
- It does not inject `SIGKILL` at runtime boundaries yet.
- It does not yet test command idempotency, independent reconstruction over a long history, index corruption, or malformed log/status lines.

## Evidence quality

The tests are small but discriminating: they fail only if startup reconstruction applies changesets that should not be committed or accepts a committed status without the required changeset. They are suitable as regression tests before changing recovery behavior.
