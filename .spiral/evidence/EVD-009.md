# Verification Evidence: Command Crash Matrix And Reconstruction Oracle

## Claim being verified

`IMP-004` expands SimplyStore's command update crash matrix and verifies restart state against an independent reconstruction oracle.

## Why this evidence exists

Prior evidence covered only one process crash boundary and repeated active-command crash safety. The command update lifecycle still had several untested commit boundaries, and the normal startup/query path alone could hide ambiguous recovery behavior.

## Result

Commands run:

```text
npm test
npm run test:durability
npx eslint src/server.mjs src/command-worker-module.mjs src/recovery.mjs test/durability-crash.mjs test/durability-helpers.mjs
git diff --check
```

Results:

- `npm test` passes with Node's built-in test runner: 10 startup/unit durability tests pass.
- `npm run test:durability` passes with Node's built-in test runner when allowed to bind localhost: 13 process durability tests pass.
- Targeted ESLint passes.
- `git diff --check` passes.

The process durability tests cover:

- production/development environments ignore configured fault points;
- crash after command log but before accepted status is not committed;
- duplicate command-log records for one accepted command ID do not replay twice;
- accepted command crashes replay to one committed state at:
  - after accepted status before response;
  - after active status before command worker;
  - before changeset write;
  - after changeset write;
  - before done status;
- crash after done status but before query update recovers committed state without replay;
- repeated active command crashes become `unsafe`;
- normal restart preserves committed state according to the reconstruction oracle.

## Failure cases / limits

- This evidence covers process crashes, not power loss or directory-fsync behavior.
- It does not classify every adversarial storage inconsistency.
- It does not prove command handlers are deterministic or idempotent under replay.
- It does not add cleanup/reset tooling for dirty datasets or unsafe commands.

## Evidence quality

This evidence materially improves durability confidence because each server restart assertion is paired with direct reconstruction from durable command status, command log, base data, and committed changesets. It remains bounded evidence for SimplyStore's current command update lifecycle, not a general production-safety claim.
