# Evidence: Conversion Offset Correction

Verified on 2026-09-17 using Node v24.7.0.

- Before the fix, the default conversion regression passed; both custom-hook
  cases failed on incorrect ranges. In the mutating-hook case, record 1's range
  was `[25,61]` while its final on-disk framing required `[25,121]`.
- After the fix, `npm test` passed all 22 tests: three conversion regressions
  plus the existing startup/durability suite. CLI regressions cover multibyte
  text, increased and decreased record lengths, hidden reference properties,
  appended anonymous records, and replacing a stale sidecar when a custom hook
  does not write one. The oracle walks on-disk byte framing independently of
  the OD-JSONTag parser's position metadata.
- `node node_modules/eslint/bin/eslint.js test/conversion-offsets.mjs` passed.
- The final parse/writer pass was exercised on the 181,724-record downstream
  `curriculum-restapi-dev/curriculum-store/data/data.jsontag`, generating an
  index only in a temporary directory. Every range matched an independent
  byte-framing scan; the source SHA-256 was unchanged. Measured elapsed time
  was 5.034 seconds, including verification. Temporary output was removed.
- `git diff --check` and staged Spiral provenance validation passed before
  implementation commit. Validation used
  `/tmp/simplystore-spiral-venv/bin/python`, since the default Python lacked
  rdflib. CLI tests required child-process execution outside the sandbox.

## Limits

The complete downstream custom conversion was not rerun. Its existing offset
file remains stale until the corrected converter is adopted and run there.
The added pass reads/materializes records with the current parser/writer;
the timing above is one local observation, not a performance guarantee.
There is no new atomic multi-file publication or crash-safety guarantee for
conversion, and command-update index hooks are not changed by this cycle.
Human acceptance and package publication remain pending.
