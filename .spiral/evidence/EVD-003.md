# Verification Evidence: Startup Recovery Repair

## Claim being verified

`IMP-001` repairs the two accepted startup recovery counterexamples from `EVD-002`:

- accepted-but-not-done changesets are not exposed as committed state;
- done commands with missing changesets fail recovery explicitly.

## Why this evidence exists

`CYC-003` accepts `EVD-002` as the first repair target. This evidence verifies that the narrow startup recovery repair satisfies that target.

Coverage is still printed and should become a meaningful project metric in a later cycle if desired.

## Failure cases / limits

- This does not prove crash safety at every update boundary.
- This does not test full server restart via HTTP.
- This does not repair unawaited command log/status appends.
- This does not test malformed command status/log lines.
- This does not test idempotent retry after lost response or crash.

## Evidence quality

The evidence directly reruns the accepted failing harness from `EVD-002`. It can detect regressions in the first two startup recovery invariants without relying on normal query behavior alone.
