# Schema identity across the query isolate

Verifies the DEF-20260926-TTZ7C-62 correction at 8638f1f (implementation
be90dd4, design d881fe1). Node 24.7.0, isolated-vm 6.2.0, Intel Core i7-1195G7.

## Regressions

Three tests in `test/query-isolate.mjs` cover the defect:

- shared, linked and cyclic schema objects compare `===` across paths; the
  guest sees the same own keys as the host, including JSONTag attributes;
  a JSONTag response of `meta.schema` equals host `JSONTag.stringify`; a JSON
  response of the cyclic schema fails promptly as circular, like host JSON;
- a schema with 26 objects and 2^25 paths returns as JSONTag, equal to host
  serialization, within the 1 s default timeout;
- schema handles are equal for shared objects, across views and across
  separately parsed copies of the schema, so identity outlives one query.

Baseline commit 49f3573 recorded the first two failing on the old
implementation (identity false; "Query execution timed out"). Restoring the
pre-fix `src/` at the final tree makes all three fail; the fixed tree passes.

## Full suite

The EVD-20260924-TTZ7C-60 command, all 14 test files, passes 205 tests with
no failures or skips (202 there, plus these three). Focused ESLint on the
changed query files passes. `git diff --check` passes for every commit.

## curriculum-store schema

Actual runtime path, slow pool, curriculum-store's 92 KB `schema.jsontag`
(281 objects, 734 shared references):

| Query | Before | After identity | After caching |
|---|---|---|---|
| `meta.schema`, JSONTag | 64 MiB exhausted, 2.4 s | 86 ms | 34 ms, 49,844 bytes |
| `meta.schema`, JSON | 64 MiB exhausted, 2.6 s | 2,806 ms | 271 ms, 4,012,890 bytes |
| `kerndoelen`, JSONTag | 28,227 bytes (expanded) | 6,957 bytes | 11 ms |
| `referentiekader`, JSON | 442 ms | 267 ms | 33 ms |

Response sizes equal host serialization of the same schema. The JSON response
is large because JSON cannot express sharing; that is not a query-engine cost.
Measurements used a disposable store with the copied schema file.

## Record queries

`scripts/benchmark-query-runtime.mjs` medians (ms) compared with
EVD-20260924-TTZ7C-60: 1,000 scan 50.7 (48.7), filter/sort/project 49.8
(52.9), serialize 84.9 (81.3); 10,000 scan 483.6 (453.3), filter/sort/project
467.6 (497.9), serialize 86.2 (81.0). Differences are within run-to-run
variation; read caching neither helps nor harms single-pass scans.

## Limits

Command workers still receive the structured-cloned schema without JSONTag
ids; this cycle changed only query workers. Guest JSONTag serialization of
query-constructed shared objects without ids still needs `crypto`, which the
isolate lacks. That is retained as a discovery, not corrected here. No
performance claim is made beyond these warm-cache measurements.
