# Verification Evidence: Legacy Index Handler Lifecycle

## Claim being verified

`IMP-009` characterizes the current legacy `index.update()` lifecycle: it is pre-commit, failure blocks canonical commit, external derived writes can remain after failure, and successful index updates can mutate canonical state.

## Why this evidence exists

The governing durability/extensibility plan requires handler-contract failure tests before broadening extension behavior and before adding integrity roots. Current index hooks are the existing after-change mechanism, so their mutation and failure semantics need executable evidence before designing a safer handler API.

The new handler tests cover:

- `index.update()` failure prevents command commit;
- external derived file written by `index.update()` can remain after command failure;
- `index.update()` can currently mutate canonical state before commit, and that mutation is committed.

## Failure cases / limits

- The evidence is characterization of the legacy hook, not proof of a new explicit handler API.
- It does not yet enforce a non-mutating `derive` phase.
- It does not test optional handler failure, finalizer metadata, or post-commit observer behavior.

## Evidence quality

This evidence is strong for current legacy index handler behavior under the server harness. It deliberately preserves uncomfortable findings, especially external derived file escape after failure, so the next contract implementation can address them explicitly.
