Results:

Important assertions now covered:

- An integrity manifest detects a same-length altered base OD-JSONTag payload.
- An integrity manifest detects a same-length altered committed changeset payload.
- Integrity-enabled loading requires a base data manifest entry.
- A full server command with integrity enabled records the committed changeset digest before `done`, and restart fails explicitly if that committed changeset is later altered.
- Existing startup tests without integrity metadata still pass, preserving default legacy compatibility.

## Failure cases / limits

- The manifest itself is not yet chained, signed, or protected from coordinated rewrite.
- Command log/status integrity remains outside this slice.
- Existing datasets need an explicit manifest entry before integrity-required startup succeeds.
- No automatic repair or manifest rebuild tool exists yet.

## Evidence quality

This is direct executable evidence for the first narrow integrity behavior and regression evidence for adjacent server/load behavior. It does not prove full tamper resistance; it proves detection of byte changes for manifest-covered base data and committed changesets.
