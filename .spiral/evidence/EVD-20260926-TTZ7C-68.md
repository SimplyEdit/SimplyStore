# Self-healing ownership evidence

Verifies the implementation at d393787 (design 2cfb2ee) for
REQ-20260926-TTZ7C-66. Node 24.7.0 on Linux; Docker `node:24-alpine`.

## Regressions

`test/store-ownership.mjs` holds ownership in separate processes killed with
SIGKILL: a running owner is refused; a killed runtime owner is taken over with
an audit record naming the previous token and PID; recovery locks, a legacy
lock without liveness, a lock whose socket is missing, and non-runtime starts
are refused; a store path too long for a socket publishes no liveness and is
refused; six concurrent contenders for a dead lock leave exactly one owner
(20 of 20 repeated runs); a leftover takeover directory blocks takeover and
administrator release removes it together with a socket-bearing lock.

`test/durability-crash.mjs`: an idle server killed with SIGKILL starts again
and serves queries; a server killed during a command now starts only as far as
"Administrative recovery required", with its active status intact and no lock
left; a SIGTERM while a slowed load is opening exits 0 without listening and
leaves no lock.

At baseline 460ef5b, eight of these failed; the running-owner and long-path
refusals already held.

`fs.cp` cannot copy socket files, which failed PL01-05's crash-image copy. The
helper now skips sockets, as `tar` and `rsync` do; the image and its
administrator unlock are otherwise unchanged. SimplyStore's backup, restore
and recovery copy individual files and never copy lock directories.

The 15-file suite passes 215 tests; `npm test` passes 141. Every changed file
lints clean; `src/` has 52 pre-existing problems against 53 on master.

## Docker, end to end

The actual curriculum-restapi-dev compose file ran with an override naming a
disposable curriculum-store copy, whose installed SimplyStore `src/` was
replaced by this branch's:

| Case | Result |
| --- | --- |
| SIGKILL (exit 137), then `up` | takeover logged, audit written, query HTTP 200 |
| Ctrl-C after healing | exit 0, lock released |
| Ctrl-C 0.5, 1, 1.5 s after the lock appears | exit 0, not listening, lock released |
| lock in the 0.11.1 format | `Store is locked`, exit 1 |

## Size and limits

Product code: +253/−30 lines (ownership +181, administrator release +33,
server +30/−16, runtime +8); tests +236; documentation in `docs/recovery.md`
and `DURABILITY.md`. This exceeds the pre-design estimate of about 150 lines,
mainly for the serialized takeover and administrator handling.

Unproven: filesystems without Unix sockets other than the long-path case,
Windows, and power loss on a real device (the modeled power-loss suite passes;
its images carry no socket). Stores shared between machines are unsupported.
