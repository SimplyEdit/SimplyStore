# Design: Derive Offsets From Final Serialized Records

Keep the legacy custom index hook in its existing pre-serialization position:
it can change canonical state, including records outside the initial changed
list. Derive physical offsets only from the final bytes, not that changed list.

Extract the existing OD-JSONTag framing validator's loop into a shared scanner
with an optional record visitor. Track global record numbers through `+N`
skips, report payload byte ranges for emitted records, and preserve all current
framing failures. The existing validation entry point delegates without a
visitor or allocating a complete index. This avoids parsing entity bodies or
resolving references to records absent from a sparse changeset.

Add a serialized-byte writer to the existing offset module. It builds the same
JSON mapping and atomically replaces the appropriate base or command sidecar
using the already-installed write-file-atomic library. Empty changesets produce
`{}`. Keep the old create/update methods for custom-hook compatibility; the
final pass overwrites their provisional output.

The command worker awaits this final write after the changeset write and before
integrity recording, the after-write fault point, and returning success. Failure
propagates through the existing failed-command path. A crash can still leave
uncommitted files; existing status-driven recovery must ignore them. This is not
a new atomic multi-file transaction or power-loss durability guarantee.

Use the same writer in conversion, replacing its extra full parse. This retains
the earlier conversion guarantee and avoids maintaining two finalization paths.

Verify with command-worker regressions for edits, additions, Unicode, leading
and interior skips, hook-introduced changes, successive changesets, empty
changesets, and failed final writes. Compare disk bytes with an independent
framing oracle. Run startup, handler, ACID, and crash/recovery suites because
command completion now awaits an additional write.
