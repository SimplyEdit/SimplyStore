# Ordered file sources and owned reader sessions

Transport ordered source descriptors (path, byte offsets, size and digest), not
open descriptors or dataset bytes. A small file-reader session owns handles and
an od-jsontag parser; queries reuse it, commands open the committed prefix for
one execution, and all exits close handles. Resolve IDs through getLineProxy.

Load default offset/ID sidecars for the base and log-authoritative committed
commands. Keep the fixed-buffer framing/hash scan: legacy sidecars have no
cryptographic binding to canonical bytes. Validate every persisted offset range
and record key against framing, and pass the loaded offsets to od-jsontag only
when the complete map agrees. Missing, malformed or stale maps use derived
offsets. Do not import custom index code during inspection/loading.

During the same scan, collect only each record's leading JSONTag metadata,
respecting quoted/escaped delimiters, and use JSONTag's own tag parser for IDs.
Skip record bodies. Merge per-record IDs in committed source order, then apply
ascending record-number precedence. Compare the composed persisted ID map with
this complete final map; use persisted IDs when equal and reconstructed IDs
otherwise. This handles removed/renamed IDs, duplicate IDs and sparse holes
without trusting an incomplete sidecar. Unusual reference-only records use the
existing parser reconstruction fallback. Lazy body errors remain storage errors
when read; startup validates framing, headers and configured full-file integrity,
not all record-body syntax.

Read-only load never rewrites sidecars or requires a new format/cache certificate.
The scan remains O(file bytes), and catalogs/IDs O(record count); the improvement
is avoiding full live-record decoding, not skipping integrity reads.

Startup inspection returns plain file sources instead of retained data/buffers.
Administrative recovery uses the same loader/session. Temporary command output
may remain buffered for the existing custom finalize(serialized, meta, uuid)
hook; it is written durably and returned as a file descriptor object. This
preserves the hook and avoids holding the whole dataset in memory. Streaming
full-dataset serialization is unnecessary once startup stops compacting it.

Worker updates must serialize with queries and replacement workers must receive
the current committed source list. Await termination before releasing store
ownership. OS/Node worker teardown closes descriptors on timeout/failure.

Alternative considered: keep a buffered fallback or merely replace query reads.
That would leave startup/recovery retaining entire datasets and duplicate modes;
a shared file-session boundary gives one implementation and test surface.

Pin the reviewed od-jsontag Git commit until a separately authorized release.
No dependency publish, remote deployment or user data mutation is part of this
implementation. Validate behavior with independent byte-offset oracles and the
existing durability suite.
