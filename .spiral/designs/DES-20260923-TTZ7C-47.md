# Ordered file sources and owned reader sessions

Transport ordered source descriptors (path, byte offsets, size and digest), not
open descriptors or dataset bytes. A small file-reader session owns handles and
an od-jsontag parser; queries reuse it, commands open the committed prefix for
one execution, and all exits close handles. Resolve IDs through getLineProxy.

Load base and log-authoritative committed ID sidecars directly. Validate their
JSON shape, record numbers and uniqueness using catalog metadata; do not read
record tags to check a present index's contents/completeness in normal startup.
Missing ID sidecars are reconstructed from their source's headers. Explicit
validateIndexes checks persisted content; rebuildIndexes ignores persisted IDs
and reconstructs in memory. Malformed present ID indexes fail normally. Offset
framing/hash scans and configured integrity validation remain unchanged.

Use the existing compact ID-to-record JSON map; no legacy format path or
duplicate-ID winner selection. Apply each changeset by removing mappings whose
records it replaces, then inserting its IDs. Two distinct current records with
the same ID are an error; swaps and same-record updates remain valid.

Extract IDs from final serialized bytes after mutation hooks. Prepare the ID
map and check global uniqueness before publishing the canonical changeset.
The core finalizeIndex boundary awaits custom finalization, durably writes the
canonical ID sidecar, and updates returned metadata. Custom finalizers retain
their call contract and control their own offset behavior, but cannot bypass
core ID finalization. Conversion does the same prepublication preparation.
Capture the expected serialized digest before custom finalization and reject
changes to canonical bytes before command success. Empty commands publish {}.

The loader and commit preparation share removal/uniqueness rules. Command
preparation uses a snapshot of committed IDs, not a mutable hook/parser map.
Tests must compare live results with restart and prove complete indexes avoid
header parsing. No persistent reconstruction or canonical rewrite occurs at
startup. The only byte scan remains framing/hash validation unless an ID index
is missing or maintenance validation/reconstruction is requested.

Startup inspection returns plain file sources instead of retained data/buffers.
Administrative recovery uses the same loader/session. Temporary command output
may remain buffered for the existing custom finalize(serialized, meta, uuid)
hook; it is written durably and returned as a file descriptor object. This
preserves the hook and avoids holding the whole dataset in memory. Streaming
full-dataset serialization is unnecessary once startup stops compacting it.

Worker updates must serialize with queries and replacement workers must receive
the current committed source list. Await termination before releasing store
ownership. OS/Node worker teardown closes descriptors on timeout/failure.

Alternative considered: keep a buffered fallback or merely replace query reads.
That would leave startup/recovery retaining entire datasets and duplicate modes;
a shared file-session boundary gives one implementation and test surface.

Pin the reviewed od-jsontag Git commit until a separately authorized release.
No dependency publish, remote deployment or user data mutation is part of this
implementation. Validate behavior with independent byte-offset oracles and the
existing durability suite.
