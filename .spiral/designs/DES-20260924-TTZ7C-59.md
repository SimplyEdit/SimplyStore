# Fresh isolates and a host-authorized data view

Use isolated-vm 6.2.0, without snapshots, for each query. Keep the existing
worker pool and trusted command/storage runtime. The worker owns the established
FileDataset, offset/ID indexes and access module. Bundle the pure JAQT/JSONTag
query helpers for the isolate; do not supply an import resolver or Node globals.

The benchmark used a parser inside the guest and raw record callbacks. That is
not an authorization boundary: parser internals and same-realm mutable library
objects must not expose raw denied fields. Existing access modules are trusted
Node modules. Rather than moving them into a hostile realm or stringifying
functions and silently losing their imports/closures, keep parsing and access
checks on the host. Supply an isolate-local read-only view with copied values
and private synchronous callbacks. A disposable prototype scanned 10,000 records
in about 362–430 ms through this view; the chosen boundary still warrants real
integration measurements.

References identify stable host identities, not host objects or paths on disk.
A data object reuses its record number, and a data array its record number plus
property path: od-jsontag stores every object as a record, so an array has one
owning path. Schema objects and arrays may be shared or cyclic, so a path does
not identify them. Number them once per parsed schema by a deterministic walk
in property order; the same schema yields the same handles in every worker and
query. Handles remain private to the bridge and add no query-visible property,
symbol or value. Existing JSONTag `id` attributes are not reused because not
every schema object has one. Resolve references through the host for every
operation so bounded record caches remain effective. Preserve guest identity
with weak references keyed by these references, so one host object is one
guest object and JSONTag serialization retains links.

Structured cloning keeps shared objects but drops JSONTag metadata, including
the schema's `id`s that JSONTag links name. The runtime therefore passes the
loaded schema's original JSONTag text to each query worker, which parses it
once at initialization. Query responses use the schema file's ids.

Data cannot change during a query: updates are serialized with queries and
each query has a fresh isolate. A guest proxy therefore caches its keys and
property reads for the query's lifetime, so repeatedly traversing shared
objects does not repeat host calls. Grants still apply on the first read. The
cache uses built-ins captured before query code runs. Return scalars, tagged scalar copies and descriptions of
object/array views. Expose only ordinary property names and JSONTag's public
metadata symbols. Do not forward parser-private symbols, prototypes, methods,
raw buffers, source handles or isolated-vm References. Mutating the view throws;
mutating a copied tagged scalar cannot modify stored data. Enforce grants on
reads, existence, enumeration and descriptors in the host realm.

Each query receives fresh globals/root/data/meta/request and helper instances.
Run pointer selection, the user script and result serialization inside the
isolate's deadline. Capture the serializer privately so its Reference never
enters guest code. Only primitive response text crosses back. Bound UTF-8 result
size before copying it to Node; reject asynchronous query results. Configure
64 MiB isolate memory and 10 MiB result bytes by default, with explicit positive
finite validation. Also limit individual bridge copies. Keep callback values
small and never pass an untrusted function to a host API.

An outer pool deadline replaces a stuck query worker and initializes its
replacement from the current committed head. Updates remain serialized with
queries. Initialization/update failures keep the existing fail-stop behavior.
Storage failure remains host-owned FileParser state, including when a query
catches its exception. Guest-thrown properties never classify storage failure.
Always release references and dispose the isolate, including errors/timeouts.

The native engine's heap limit is not an OS process/RSS limit, and this worker
thread integration does not claim resilience against every native V8 failure.
It is the authorized query-engine step, not internet-exposure certification.
A separate OS process boundary remains a deployment-hardening consideration.

Validate the actual runtime API, grant reflection, Unicode/tagged values, JAQT,
updates/restart, hostile serialization, imports and post-failure queries. Keep
accepted durability tests. Benchmarks must distinguish this view from the prior
raw-record bridge. The portable od-jsontag branch remains separate work; this
integration can preserve the accepted host parser dependency without publishing
or depending on an uncommitted cross-repository change.

Muze's replaceable-boundary and library-inspectability preferences favour one
small engine adapter and an explicit data-view contract over a general sandbox
framework. No engine selection option or VM2 fallback is needed.
