# File-backed runtime boundary

Confirmed scope: make files the sole dataset source for live queries, commands,
startup assessment and administrative replay. SharedArrayBuffer is currently
used for the loaded base and all committed changesets. Worker ID lookup assumes
all records have cache entries. Inspection also retains full file buffers.
Those observed paths prevent the requested outcome despite file support in the
new dependency. The current 118-test suite passed with the hardened dependency.

Keep the accepted format, remote API and durability semantics. Immutable base
and changeset files remain available while a store owns its dataset; each worker
owns its descriptors. Index metadata may scale with record count; command edits
and response/output buffers may scale with a command or query. Bounded clean
query caching is the dependency contract, not constant total memory. Full
startup integrity scanning remains necessary, but can use bounded byte buffers.

The human's instruction follows the concrete integration explanation and is the
commitment boundary; no second permission ceremony is needed.
