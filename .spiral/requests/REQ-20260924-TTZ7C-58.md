# Restricted isolated-vm query workers

Replace VM2 query execution with isolated-vm, selected explicitly after the
retained engine comparison. Preserve the remote JavaScript query interface,
JAQT and JSONTag helpers, root/data/request/meta, path browsing, ID lookup,
read-only grants, committed-view updates, and storage-failure classification.
Queries cannot import modules or access Node, filesystem, network, databases,
or raw host references. File reads and grants must be controlled by the host.

Execution and serialization are bounded by the selected normal/slow timeout.
Configure an isolate memory budget and a maximum encoded response size. Reject
bad limits and fail queries clearly when limits are exceeded. A fresh query
must not inherit another query's global or prototype mutations. Failed queries
must not make later queries hang or publish a newer view out of order.

Evidence: real worker/runtime tests for helpers, tagged responses, Unicode,
links, ID/schema access, grants (including reflection), mutation attempts,
imports and dynamic code, timeout during execution and serialization, oversized
results, committed updates/restart, and forged versus actual storage failures.
Retain the accepted durability regression tests. Measure the integrated data
boundary independently from the raw-parser engine benchmark.

This is a query execution migration, not public-deployment certification or an
entire-server runtime change. History/audit functionality and its UI are later
work. Disk formats, command execution, integrity and recovery contracts remain
unchanged. No snapshots or selectable VM2 fallback.
