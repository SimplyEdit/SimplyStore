# Request: Correct Command Changeset Offsets

After the maintainer asked whether commands suffer the same defect, a direct
command-worker probe produced stored offsets `{0:[4,20],1:[25,39]}` for a
changeset whose records required `{0:[4,20],1:[25,81],3:[89,110]}`. The new
record was omitted and the updated record retained its original end position.
The maintainer then explicitly required fixing it: "But it needs fixing ...".

Successful commands must persist an offset sidecar matching every record in
the final changeset, including newly allocated records and index-hook changes.
Skip records must preserve global record numbers; unchanged records must not
appear. Offsets count UTF-8 bytes within that changeset file. Empty changesets
have an empty index. The sidecar must be complete before success is returned.

Preserve custom hook mutation semantics, command status and integrity ordering,
existing disk shapes, and restart behavior. Index write failure must prevent
success. Reuse the final-byte derivation for base conversion where practical;
do not republish packages or repair downstream files as part of this change.
