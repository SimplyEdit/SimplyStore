# Request: Correct And Clarify Runtime Boundaries

Retain the accepted architecture while correcting the reviewed regressions.

| Criterion | Required evidence |
| --- | --- |
| R1 Closure | Every overlapping/repeated close waits for the same cleanup, including any failure. SIGTERM followed by SIGINT must wait for active commands, release healthy ownership and exit successfully only after completion. |
| R2 Acceptance | If storage fails during persistence, no new success acknowledgment or queue insertion follows. Retain written evidence, reject subsequent admission and keep ownership. |
| R3 Compatibility | Parsed commands with a valid existing ID return the current status before new-command name validation. Incomplete new commands still return 422 and write nothing. |
| R4 Readability | Inspection and approved-command recovery coordinators express phases at a consistent abstraction level; parsing, persistence and prefix bookkeeping belong in cohesive supporting methods. No new class hierarchy or general infrastructure. |
| R5 Preservation | Log order, durable barriers, query publication, recovery predicates, audit reports and lock retention remain covered by existing regression suites. No disk-format or public endpoint changes. |
| R6 Review boundary | Record the already requested AGENTS.md acceptance/integration clarification. Finish at evaluation; human acceptance and integration remain separate. |

Use deterministic runtime interleavings and a real subprocess signal test in
addition to the existing suites. Test awaited outcomes, not promise identity or
method names. Readability needs human/code review as well as behavioral evidence.
