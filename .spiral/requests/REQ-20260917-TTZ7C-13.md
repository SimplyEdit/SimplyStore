# Request: Customizable Index Finalization

The maintainer accepted the proposed two-stage indexing arrangement and said:
"I think we should do that, since curriculum-store changes the index.* methods,
and I want those to work out of the box."

Conversion and command workers currently call the offset module directly after
custom create/update hooks. A custom index module cannot participate in or
override that final step. Curriculum-store's existing wrapper exposes only
create/update/load, so adding a mandatory finalize method would break it.

Route post-serialization finalization through SimplyStore's index module. Honor
an optional custom finalize method, await completion, and propagate errors.
Existing wrappers without the method must receive default offset finalization
automatically. Retain correct final-byte offsets and legacy hook semantics.
Verify the unchanged curriculum-store wrapper on representative graph fixtures.
No package publication, downstream dependency changes, or live data repair.
