# Self-healing store ownership

Derived from SRC-20260926-TTZ7C-65.

1. A server that stops during startup releases its ownership. A stop request
   before the store is open lets opening finish, then closes normally.
2. When a previous server's ownership remains after a crash, SIGKILL or power
   loss, the next server start takes it over only when the previous owner is
   proven gone, records the takeover, and then applies the unchanged strict
   startup assessment. Unfinished commands still require administrator
   recovery; nothing is rerun automatically.
3. When proof is unavailable (the owner may be alive, the lock predates this
   mechanism, the lock belongs to an administrative operation, the filesystem
   or path cannot hold the proof, or its state is incomplete), startup refuses
   exactly as before and the documented administrator release still works.
4. Two concurrent starts never both own the store.

Assumption made explicit: one machine uses a store directory at a time. The
proof is local to the kernel that runs the owner.

Acceptance: a server killed with SIGKILL while idle starts again without manual
release; a server killed during a command starts no further than administrator
recovery required; a running owner, a legacy lock and a recovery lock are never
taken over; concurrent takeovers leave exactly one owner; a stop during startup
leaves no lock; administrator unlock handles the new lock contents.
