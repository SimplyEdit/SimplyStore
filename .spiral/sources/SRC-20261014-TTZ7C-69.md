# Source: queryable object and command history

## Source kind

Retained maintainer conversation on 2026-10-14, following inspection of the
current SimplyStore and curriculum-store query and command paths.

## What was actually expressed or observed

The maintainer wants the next SimplyStore cycle to expose version history to
JavaScript queries. The initial direction was access to every successfully run
command, including its author, timestamp, commit message and associated dataset,
and the ability to identify the command that produced an object's current and
previous versions.

After reviewing current behavior and possible representations, the maintainer
settled the first slice:

- use one timestamp: the timestamp of the dataset file;
- retain the submitted author without additional authentication or validation;
- given an object, expose its version/command history with timestamp, author and
  commit message;
- allow a query to find the other objects in the same specific version;
- do not add separate authorization for historical versions;
- defer switching a whole query to a complete historical dataset, while keeping
  that as a desired later capability.

The maintainer then instructed: “Lets start a cycle with this intent and design.”

The conversation also established preferred semantics for the first slice. The
base dataset is version zero; each successfully committed command is the next
global version. A version's objects are the ID-bearing records written by that
command's changeset. Historical objects are immutable query views. The future
complete-dataset capability remains distinct from a command's changed objects.

## Limitations / uncertainty

“Dataset file timestamp” means the filesystem modification time captured for
the base or changeset file. It is useful display/audit metadata, but copying or
restoring files may change it; it is not an independently sealed commit time.

The exact query API remains a design concern provided it supports the settled
outcomes. Complete historical dataset switching is explicitly deferred.
