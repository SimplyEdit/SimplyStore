# Source: keep original command input outside query workers

## Source kind

Retained maintainer evaluation feedback on 2026-10-14 for the implemented
queryable object-history cycle.

## What was actually expressed

After reviewing the lazy command-input implementation, the maintainer questioned
whether its complexity was justified because the command information needed by
queries is small. The implementation review established that laziness avoided
replicating unbounded original payloads but did not reduce inspection I/O.

The maintainer decided:

> Lets do that. We can create seperate tools to do more with original command
> inputs when we need it, I don't think the query worker will ever need that.

Accordingly, query workers should receive only the compact successful-command
metadata used for history: ID, name, author, message, dataset-file timestamp and
version. They should not expose original command input or access the command log.
Future inspection of original inputs belongs in separate tooling.

## Origin / locator

Conversation with the SimplyStore maintainer during evaluation of
CYC-20261014-TTZ7C-73 in the shared development workspace.

## Primary evidence availability

Retained in the collaboration transcript and summarized here.

## Provenance confidence

Explicit maintainer direction after inspecting the implemented trade-off.

## Limitations / uncertainty

This does not remove or rewrite original inputs in the authoritative command
log. It narrows only the JavaScript query surface and its worker messages.
