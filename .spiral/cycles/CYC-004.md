# Cycle: Full Startup Recovery Harness

## Analyze

Project state / prior evaluation that makes this cycle relevant:

`CYC-003` repaired the first startup recovery failures at the recovery-helper/load-worker seam and was accepted by the human.

Nearest important risk / uncertainty / desired movement:

The current passing tests do not yet prove the durable command-status and command-log file parsing path that `server.mjs` uses during startup.

Relevant human direction / feedback:

The human accepted the proposed next cycle: prove the full startup selection path from durable status/log files to recovered state.

## Plan

### Cycle goal

Add a fuller startup recovery harness that uses real `command-status.jsontag` and `command-log.jsontag` files to verify committed command selection and pending command replay classification.

### Why now

This is the next smallest evidence-producing step after CYC-003. It expands from low-level loader behavior to durable startup inputs without adding crash injection or broader durability machinery.

### Current starting evidence

- `CYC-003` passes low-level recovery tests.
- `EVD-003` records that full command-status/command-log parsing remains untested.
- `server.mjs` still owns status/log parsing internally.

### Evaluation basis

`npm test` should pass tests showing that:

- only the latest `done` status for a command selects a committed changeset;
- accepted and failed commands do not select committed changesets;
- accepted commands in the command log are classified as pending replay work;
- done and failed commands in the command log are not replayed;
- recovery from durable status files plus changesets produces the expected state.

### Likely work

- Move or mirror startup status/log parsing into `src/recovery.mjs`.
- Update `server.mjs` to use the shared recovery helpers.
- Add TAP tests that create real temporary command-status and command-log files.
- Preserve passing evidence in `EVD-004`.

### Explicit non-goals

- Add real child-process server restart.
- Add `SIGKILL` fault injection.
- Change command acceptance/outcome append ordering.
- Add integrity hashing.
- Add after-change handler contracts.
- Clean up unrelated `runNextCommand()` structure.

### Pause / re-plan conditions

- Sharing status/log parsing requires changing durable file formats.
- Full startup selection cannot be tested without starting a long-lived HTTP server.
- The repair would broaden into command lifecycle or transaction semantics.

## Act

Important artifacts / semantic commits produced:

- `IMP-001` revised: startup recovery selection now includes shared durable status/log parsing and replay classification.
- `test/durability-startup.mjs` extended with command-status and command-log file fixtures.

Material implementation decisions or deviations from the initial likely work:

- Shared the existing `server.mjs` parsing semantics through `src/recovery.mjs` rather than adding a server-process test harness.
- Kept command replay task construction shape compatible by passing task defaults into `loadCommandLog`.

Out-of-scope discoveries retained for later:

- Full HTTP server restart remains untested.
- Malformed/truncated status/log lines remain unclassified.
- The deferred `runNextCommand()` cleanup remains out of scope.
