# Isolated query execution

Goal: register the selected isolated-vm engine and replace VM2 query execution
with an evaluable, restricted integration that preserves SimplyStore behavior.

Status: Accepted on 2026-09-24. Human commitment: explicit engine choice after benchmark and
capability evidence, retained in SRC-20260924-TTZ7C-57. Classification: continue the
file-backed/sandbox roadmap; engine investigation has produced a selection.
Object history remains the next target, with UI deferred.

Branch: spiral/CYC-20260924-TTZ7C-56-isolated-vm, created from authoritative master
029b36f. Branch identity checked when opening the cycle. CYC-44 and CYC-51 are
accepted and integrated on master; the previous context's pending-integration
text was stale.

In scope: query engine, controlled data/grant interface, supplied query helpers,
JSON/JSONTag responses, resource limits, dependency/runtime documentation and
regression/performance evidence. No imports or general host capabilities for
queries. Trusted command execution and file/integrity formats remain governed
by their accepted contracts. Hostile queries may lose their worker/session.

Non-goals: history implementation, UI work, broad public-deployment claims,
engine fallback framework, snapshots, full-history rebuild and unrelated cleanup.

Evaluation ready: isolated-vm replaces VM2, with a fresh isolate per query and
host-authorized read-only views. The host retains the existing parser and grants;
this resolves the authority gap in the raw-record probe. Execution/serialization,
memory, output and outer-worker limits are covered. EVD-20260924-TTZ7C-60 records
202 passing tests, clean focused lint, package checks, copied-example queries,
and actual worker-path timings. Implementation is at bd507554a2fed6f77322ef38a98839f127d810db.

The final scan benchmark is about 453 ms for 10,000 records; filtering/sorting/
projection is about 498 ms. The measured result supports the selected engine,
with the synthetic/warm-cache scope retained. No snapshots or whole-process
memory/crash boundary is claimed. Human acceptance is recorded below; integration
remains pending.

## Human acceptance and version

On 2026-09-24, the maintainer explicitly instructed:

> mark this cycle as accepted, bump simplystore version to 0.11.0 (if that is correct)

This accepts the implementation at `bd8f8eb3ee617c5f9e9198f234725ef7ab5b4201`, including the
published od-jsontag 0.5.0 dependency and Node parser entry point. The full suite
was rerun against that published package: 202 tests passed, focused lint passed,
and queries against a disposable copy of the example store succeeded.

The maintainer emphasized that increased security is the purpose of the change;
keeping performance comparable to VM2, with modest improvements on larger
queries, is a welcome secondary result. Acceptance retains the documented limits
on whole-process memory/crash isolation and public deployment claims.

SimplyStore is bumped from 0.10.3 to 0.11.0. A minor increment is appropriate for
this pre-1.0 release's engine replacement, Node 22+ requirement, startup flag,
and query capability/limit changes. No release tag or npm publication is made
by this version change. The cycle branch identity was verified before recording
acceptance. The branch is ready for a separately authorized normal merge into
master; no next cycle has been opened.
