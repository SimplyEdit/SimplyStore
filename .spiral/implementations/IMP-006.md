# Implementation: Malformed OD-JSONTag Storage Classification

## Scope

Startup validation for malformed or truncated OD-JSONTag base data and committed changeset files.

## Observable behavior

- Base OD-JSONTag data is checked for valid record framing before parsing.
- Committed changeset OD-JSONTag data is checked for valid record framing before parsing.
- Malformed or non-OD-JSONTag base data refuses startup reconstruction.
- Malformed or non-OD-JSONTag committed changesets refuse startup reconstruction.
- Truncated committed changeset payloads refuse startup reconstruction even when lazy parsing could otherwise initially hide the bad record.
- Malformed uncommitted changeset files are ignored when their command is not committed.
- Valid OD-JSONTag `+N` changeset skip records are accepted.

## Repository locations

| Path / symbol | Role |
|---|---|
| `src/recovery.mjs#assertOdJsonTagFraming` | Validates OD-JSONTag record framing and skip records. |
| `src/load-worker.mjs` | Applies framing validation to base data and committed changesets before parsing. |
| `test/durability-startup.mjs` | Adversarial startup/recovery tests for OD-JSONTag durable files. |

## Effective provenance

This implementation realizes `CYC-012` and the `DES-001` detectable-corruption invariant for malformed/truncated OD-JSONTag durable data.

## Important implementation decisions

- The durable OD-JSONTag format is not changed.
- Validation is a byte-framing check, not a semantic integrity check.
- The validator understands OD-JSONTag changeset skip records such as `+1`.
- The validation runs only for files that participate in committed startup reconstruction.

## New dependencies / capabilities / permissions

No new package dependencies.

## Known limits

- Well-formed malicious changeset alteration is not detectable without future integrity metadata.
- The validator does not prove that changeset content corresponds to the command that produced it.
- No cleanup/reset/repair tooling is added.
