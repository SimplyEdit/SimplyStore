# Implementation: Independent Power-Loss Baseline

Implements DES-20260919-TTZ7C-21 as a new isolated test suite. No `src/` or
production script behavior changes are included.

- `test/power-loss-preload.mjs`: explicitly enabled, store-scoped I/O tracing and
  faults, inherited by disposable server workers; synced-byte snapshots and
  namespace publication observations live outside the failed storage domain.
- `test/power-loss-helpers.mjs`: external client observations, bounded waits,
  abrupt shutdown, copied crash images, trace-constrained filename loss, and
  isolated expected-failure invariant reporting.
- `test/power-loss-baseline.mjs`: 21 scenarios covering normal persistence,
  missing publications, corruption, I/O errors and short writes, effects on
  replay, later-dataset guards, input completeness, concurrent order, and a
  positive directory-sync model control.
- `package.json`: `test:power-loss` and `test:power-loss:strict` scripts. Strict
  mode exposes requirement failures; normal baseline uses explicit nested TODO
  assertions while keeping harness/control failures fatal.
- `docs/power-loss-baseline.md`: fault matrix, commands, current observations,
  independence limits, and remaining cycle work.

The test-only custom finalizer in PL21 supplies a directory sync as a positive
control; it is not a production fix. Policy fixtures and torn-record corruption
are explicitly distinguished from permitted unsynced-data/name-loss models.
The partial-write injection actually writes a shorter buffer through the current
dependency; it does not merely fabricate an error return.

This new suite adds a separate evidence mechanism without changing the existing
durability helper or runtime implementation units. Verification results belong
in EVD-20260919-TTZ7C-23 after this implementation has a committed version.
