# Implementation: Startup Recovery Command Selection

## Scope

Startup reconstruction now applies only committed command changesets and refuses recovery when a committed changeset file is missing.

## Observable behavior

- A status entry whose latest status is `accepted` is not selected for startup reconstruction.
- A status entry whose latest status is `done` is selected for startup reconstruction.
- If a selected committed changeset file is missing, the load worker throws an explicit recovery error.

## Repository locations

| Path / symbol | Role |
|---|---|
| `src/recovery.mjs#getCommittedCommandIds` | Selects committed command IDs from status map. |
| `src/recovery.mjs#assertChangesetExists` | Fails recovery if a committed changeset file is missing. |
| `src/server.mjs#main` | Uses committed command IDs for startup data loading. |
| `src/load-worker.mjs` | Requires each supplied committed changeset file before parsing it. |
| `test/durability-startup.mjs` | Regression harness for the repaired recovery behavior. |
| `package.json#scripts.test` | Makes `npm test` use explicit zero coverage thresholds so current assertion results determine command success. |

## Important implementation decisions

- `done` remains the current committed status term. This repair does not rename durable status vocabulary.
- The loader remains a low-level component: it trusts the caller to pass committed command IDs, but now treats every supplied command ID as required.
- The status-selection rule lives in a small `src/recovery.mjs` helper so tests and server startup use the same policy.
- The repair does not introduce crash fault points, hashing, handler phases, or post-commit extension seams.
- The `npm test` script now sets tap coverage thresholds to `0` explicitly. Node-tap's effective default was enforcing 100% thresholds, causing green assertions to exit with code 1. Coverage remains reported; it is not currently used as the acceptance gate.

## New dependencies / capabilities / permissions

No new package dependencies.

## Known limits

- The harness still exercises the load worker and recovery helper, not a full HTTP server process restart.
- Command log/status parsing remains inside `server.mjs` and is not yet exported or independently tested.
- Missing base dataset behavior is not changed by this slice.
- Append ordering and unawaited command log/status writes remain unresolved.
- Real `SIGKILL` fault injection is deferred.
