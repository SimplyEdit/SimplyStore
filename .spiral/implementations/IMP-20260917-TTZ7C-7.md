# Implementation: Final Conversion Offsets

`scripts/convert.mjs` passes the final serialization to the shared offset writer
after writing the data. The framing scanner generates fresh positions without
parsing entity bodies. This replaces the initial full readback in response to
the maintainer's command-offset extension. The custom create hook still runs
once, and the CLI and offset format remain unchanged.

`test/conversion-offsets.mjs` exercises the CLI and independently walks UTF-8
record framing. Before the fix, default conversion passed while the two custom
hook cases failed: a changed record ended at byte 121 but its stored range ended
at byte 61, and a hook writing no sidecar left the previous index untouched.
The tests also cover shrinking text, hidden reference properties, appended
records, and stale extra entries. They are included in `npm test`.

The predecessor first governed this converter using a full parser readback.
The current version preserves that correction's final-byte guarantee while
sharing the scanner/writer introduced for command changesets in
IMP-20260917-TTZ7C-11. Its lineage and new design are recorded in Turtle.
