# Implementation: ACID Baseline Tests

## Scope

Focused server-level tests for SimplyStore's non-durability ACID claims and duplicate command ID idempotency.

## Observable behavior

- `npm run test:acid` runs the ACID baseline server suite separately from `npm test`.
- Atomicity: a command that mutates data and then throws ends as `failed`, does not write a committed changeset, and does not change query-visible or reconstructed committed state.
- Isolation: a JavaScript query that tries to mutate `data` is rejected with `422`, and later queries still see unchanged committed state.
- Narrow consistency: a query during an active command sees the previous committed state, and later queries see the committed new state only after command completion.
- Idempotency: posting the same command ID twice acknowledges the duplicate without applying the command twice, including after restart.

## Repository locations

| Path / symbol | Role |
|---|---|
| `package.json#scripts.test:acid` | Separate server-level ACID baseline test command. |
| `test/acid-baseline.mjs` | ACID smoke tests. |
| `test/durability-helpers.mjs#makeServerFixture` | Customizable server fixture setup shared by durability and ACID tests. |

## Effective provenance

This implementation realizes `CYC-011`, caused by the human-approved planning check to test valuable non-durability ACID claims before returning to deeper durability work.

## Important implementation decisions

- The tests start real SimplyStore servers and therefore live outside the normal `npm test` path.
- The cycle does not change product behavior.
- Consistency is tested as a core-system claim about committed snapshots, not as arbitrary application-domain validation.

## New dependencies / capabilities / permissions

No new package dependencies.

The `test:acid` suite binds ephemeral localhost ports.

## Known limits

- The tests are smoke-level ACID evidence, not a complete formal proof.
- Domain consistency depends on application command handlers and is not proven here.
- Duplicate command ID response semantics may need clearer API documentation later.
