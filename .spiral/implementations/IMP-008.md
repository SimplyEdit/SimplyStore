# Implementation: Spiral Core Process Guidance Adoption

## Scope

Process-only update that refreshes the `.spiral-core` submodule and adopts upstream process guardrails in SimplyStore's local instructions and project context.

## Observable behavior

- `.spiral-core` points at upstream commit `3111b784531e327da75801f5ba8b61e891341d5f`.
- Local agent instructions no longer claim the brownfield intake is incomplete.
- Local agent instructions identify `SRC-001`, `REQ-001`, and `DES-001` as the governing durability/production-readiness plan references.
- Future durability/production-readiness cycle proposals must re-read those references, identify current position, reconcile recent evidence, and classify the proposal as continue, revise, or deliberate deviation.
- Local agent instructions and project context now distinguish discourse, commitment, and execution so tentative human suggestions do not silently become implementation authority.
- Local agent instructions and project context now prioritize risk/uncertainty by downstream leverage, late-discovery cost, and cheap falsifiability rather than horizon labels alone.
- Project context records the updated Spiral core commit and active culture/warning profile source commit.

## Effective provenance

This implementation originally realized `CYC-014`, adopting upstream Spiral Developer plan-continuity guidance in SimplyStore's local process.

This revision follows the human's 2026-08-18 process-maintenance request to update `.spiral-core` again and check for applicable process updates while `CYC-016` remains active for evaluation.

## Important implementation decisions

- No SimplyStore product/runtime code changed.
- Existing cycle records were not rewritten to the new upstream cycle template.
- The durability/extensibility plan was not revised; the new local process says to reconcile against it before choosing next cycles.
- The new discourse/commitment/execution guidance is recorded locally as an operating rule, not as a new artifact status system.
- The new risk-leverage guidance is recorded locally as a planning heuristic, not as a mandatory scoring matrix.

## New dependencies / capabilities / permissions

No new package dependencies. Network access was used to fetch the `.spiral-core` Git submodule update.

## Known limits

- The local process update does not validate all historical Spiral artifacts against the updated core.
- Future agents still need to actually follow the plan-continuity step during next-cycle planning.
- Future agents still need to apply discourse/commitment/execution and risk-leverage guidance proportionately rather than turning it into ceremony.
