# Implementation: Optional Durable File Integrity Manifest

## Scope

Implement the first narrow integrity-detection mechanism for durable OD-JSONTag data.

## Observable behavior

- `src/integrity.mjs` provides SHA-256 digest helpers, append-readable integrity manifest parsing, digest record appending, and explicit mismatch/missing-entry failures.
- `src/server.mjs` enables integrity verification when `options.integrity`, `options.integrityFile`, or the default integrity sidecar file is present.
- `src/load-worker.mjs` verifies base data and committed changesets against the manifest before OD-JSONTag framing validation and parsing.
- `src/command-worker-module.mjs` appends a changeset digest after the changeset file is written and before the existing post-changeset fault point / `done` status path.
- Startup tests cover same-length payload alteration for base data and committed changesets, plus required missing manifest entries.
- Full-server durability tests cover an integrity-enabled command writing the changeset digest before `done`, then refusing restart after the committed changeset is altered.

## Important implementation decisions

- Existing datasets without an integrity manifest remain loadable by default.
- The default sidecar path is derived from the data file, for example `data.integrity.jsontag` for `data.jsontag`.
- Manifest entries store paths relative to the manifest directory so the file stays inspectable and movable with its dataset directory.
- Manifest records are append-readable and latest-wins by file key, matching SimplyStore's existing simple log style.
- The first integrity scope is base data plus committed changeset files only. Command log/status integrity remains out of scope.

## New dependencies / capabilities / permissions

No package dependency was added. SHA-256 uses Node's built-in `crypto` module.

## Known limits

- Enabling integrity for an existing dataset requires a manifest entry for the base data before startup succeeds.
- The first mechanism detects byte changes to files that have manifest entries; it does not attempt recovery or prove command log/status authenticity.
- The sidecar manifest itself is not yet chained or signed, so a malicious actor able to rewrite both data and manifest can still hide alteration.
