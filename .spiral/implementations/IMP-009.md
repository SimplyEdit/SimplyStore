# Implementation: Legacy Index Handler Lifecycle Characterization

## Scope

Server-level characterization tests for the current legacy `index.update()` lifecycle and a dedicated npm script to run them separately from `npm test`.

## Observable behavior

- `npm run test:handlers` runs `test/after-change-handlers.mjs`.
- A thrown `index.update()` error causes the command to become `failed`.
- When `index.update()` fails, canonical state remains unchanged, reconstruction stays at the previous committed state, and no per-command changeset is written.
- If `index.update()` writes an external derived file and then throws, the command still fails but the external file remains on disk.
- A successful `index.update()` can currently mutate canonical state before commit, and that mutation is included in live/reconstructed committed state.

## Repository locations

| Path / symbol | Role |
|---|---|
| `test/after-change-handlers.mjs` | Characterizes current legacy index handler mutation and failure semantics. |
| `package.json#scripts.test:handlers` | Separate server-level handler characterization test command. |

## Effective provenance

This implementation realizes CYC-015 and provides executable evidence for `DES-002`.

## Important implementation decisions

- No SimplyStore runtime/product code changed in this implementation.
- The tests intentionally characterize current legacy behavior, including behavior that future explicit handler contracts may restrict.
- The handler suite is separate from `npm test` because it starts full SimplyStore server processes.

## New dependencies / capabilities / permissions

No new package dependencies.

## Known limits

- The tests do not introduce the new explicit handler API.
- The tests do not prove optional handler behavior, finalizer metadata, or post-commit observer behavior.
- The tests do not clean up arbitrary external files written by a handler beyond the temporary fixture directory.
