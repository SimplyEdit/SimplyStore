# Implementation: Process Crash Fault Harness

## Scope

Runtime environment validation, dormant test-only fault points, awaited command-path durable appends, and the first process-level crash/restart durability harness.

## Observable behavior

- `SIMPLYSTORE_ENV` defaults to `production`.
- Valid environment values are `production`, `development`, and `test`.
- `SIMPLYSTORE_FAULT_POINT` is ignored unless `SIMPLYSTORE_ENV=test`.
- Invalid `SIMPLYSTORE_ENV` values are rejected.
- `faultPoint(name)` is a no-op outside `test`.
- In `test`, `faultPoint(name)` kills the process with `SIGKILL` when `SIMPLYSTORE_FAULT_POINT` exactly matches `name`.
- Command acceptance appends command-log and command-status records before responding `202`.
- Command outcome status appends are awaited before resolving the command runner.
- The first named process boundary is `before-command-done-status`.

## Effective provenance

This implementation realizes the first process-level crash harness slice from `DES-001`, `REQ-001`, and `CYC-007`.

## Important implementation decisions

- Fault points live in production source so tests exercise the real command lifecycle path.
- Fault points cannot activate in production/default mode.
- The first process boundary is in the server after command worker completion and before durable `done` status append.
- The test uses generated temp data, command, index, and runner files rather than the example app.
- The test asserts recovered state through `POST /query/` because wildcard query routing was not a reliable assertion path in this environment.

## New dependencies / capabilities / permissions

No new package dependencies.

The test starts child Node processes and kills one with `SIGKILL`.

The current test scripts use Node's built-in test runner. Tap is no longer part of the active test path.

## Known limits

- Only one crash boundary is covered.
- No fault point exists inside the command worker yet.
- Directory fsync and deeper filesystem durability assumptions remain unevaluated.
- Idempotent retry after lost response remains unproven.
- Reset/clean tooling for dirty datasets remains future work.
