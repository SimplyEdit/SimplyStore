# Implementation: Durable Ordered Writes And Administrative Recovery

Implements the corrected DES-24/25 within existing canonical formats, following
the maintainer's authorization to complete CYC-17. It transforms the effective
server/worker, converter/index and baseline-test implementations identified in
the companion Turtle. Existing timeout containment, awaited hooks, final offsets,
framing and optional integrity semantics remain; automatic uncertain replay and
transport-derived command inputs are deliberately removed.

`src/storage.mjs` centralizes complete writes, durable publication/appends, file
and directory barriers, permission preservation, and first-error propagation.
Default indexes retain synchronous hook compatibility with equivalent barriers.
Conversion finishes a new base, indexes, empty logs and optional integrity under
ownership, refusing overwrite. `requiredFiles` explicitly includes custom
recovery dependencies in startup checks, completion syncing and copied inventory.

`src/server.mjs` serializes acceptance through durable command/status writes and
queue insertion, then executes sequentially in log order. It passes the exact
logged command to workers, with no request object. Awaited handler/index work,
required-file barriers and done persistence precede query publication. Uncertain
storage failures stop mutation. `src/execute-worker.mjs` retains worker timeout
containment. Healthy shutdown drains accepted work and releases ownership.

`src/store-inspection.mjs` validates canonical history and reconstructs its verified
prefix without importing user modules. It distinguishes missing, corrupt and
uncommitted data, records ever-accepted history, and checks later datasets in log
order. `src/store-ownership.mjs` excludes cooperating writers using canonical
paths and durable owner records; crash locks are never automatically stolen.
Normal startup refuses missing canonical files and pending/uncertain work without
rewriting statuses or rerunning handlers.

`src/admin-recovery.mjs` and `scripts/recover.mjs` implement inspect, preview,
explicitly approved suffix recovery into a new candidate, preserved original
copies and external audit, fresh source/code validation, completion without
reexecution after an interrupted report, consistent backup/restore, offline
unlock and promotion verification. Existing status schemas/IDs are retained.
A later ever-accepted dataset blocks earlier rerun even when empty/corrupt/unsafe.
Backup copy preserves relative artifact paths and permissions, excludes unrelated
secrets, and remains portable. Restore reports known coverage and uncertainty.
Code and undeclared dependencies retain the documented administrator obligations.

Tests cover injected short writes/errors/barrier ordering, authoritative concurrent
acceptance, JSONTag command inputs without request context, process-crash policy,
read-only inspection, guards, staleness, interruption/effect witnesses, retained
digests, portable backups and code-aware promotion verification. PL15 and PL16
expectations change only as explicitly corrected by the maintainer; historical
baseline evidence remains at EVD-23. New tests have no TODO exceptions.

`scripts/power-loss-vm/` packages a disposable Linux/ext4/QEMU exercise with a
volatile NBD cache, flush/FUA persistence, independent serial observer, device
and filesystem negative controls, accepted/active/done cuts and commit timings.
It never touches a host block device. Results belong in EVD-27 after this
implementation has an exact committed revision.

Operational documentation is in `DURABILITY.md`, `docs/recovery.md`, and
`docs/power-loss-filesystem.md`. Full rebuild remains contract-only. Physical
hardware certification, exhaustive faults, arbitrary effect rollback, deployment,
release and integration are outside this implementation.

The final acceptance examples additionally exercise exactly the verified A / missing
B / waiting C / missing D suffix, disclosed loss from an older backup, and
identical versus conflicting historical duplicate IDs. These add verification
coverage without changing the committed runtime or VM exercise.

## JAQT readability refactor during review

The maintainer approved using JAQT and named intermediate results where they
clarify the cycle code. Reviewed source/scripts for data-selection expressions;
the useful changes are in server startup diagnostics, inspection's later-dataset
and readiness queries, and administrator recovery/backup comparisons. Existing
simple array operations, sequential I/O and mutation loops remain direct code.

JAQT 0.10.6 is already a dependency. Query patterns operate on inspected command
records with established string statuses/IDs and boolean flags; truthy diagnostic
fields use Boolean predicates. Query order remains command-log order. Public
plan/report collections and later-dataset IDs are materialized as ordinary arrays
so JAQT proxies do not change cloning or public data contracts. Optional report
properties keep their prior undefined/omitted behavior.

The backup-coverage predicate now names command/status matching separately from
surviving-byte comparison. Named stages also replace dense canonical-path and
code-hash expressions where JAQT would not improve the operation. Tests cover
backup differences and unchanged plain-data output alongside the existing suite.
This is a behavior-preserving refactor; persistence boundaries, formats, recovery
eligibility and administrator authority are unchanged.

## Example initialization correction

The example now exposes `npm run build`, invoking the existing converter to
create the base, indexes and empty logs before startup. Its README documents
that one-time initialization and overwrite refusal, and uses the HTTP URL served
by the example. No import script or full command rebuild feature is added.

The converter passed an empty base URL to the mutable OD-JSONTag parser. When
indexing forces lazy parsing of tagged URLs in the Star Wars dataset, URL
validation fails even for absolute URLs. Use the parser's default valid URL base
while preserving mutable indexing. Report caught conversion errors with a nonzero
exit status so thrown parser diagnostics remain visible. Failed conversions still
retain ownership for assessment; successful initialization releases it.

Regression coverage converts the actual bundled dataset, verifies all final
record offsets and reads typed URL values, including a linked homeworld. No
canonical format, storage barrier or existing-store overwrite policy changes.

## Cycle 44: File-backed durability integration

Command workers now open immutable file sources in a fresh mutable session,
serialize only their changes into an ordinary Buffer for existing index hooks,
and return a scanned source descriptor. Persist/write/finalize/integrity ordering
is preserved. A changed canonical file after finalization is refused. Default
index loaders now use the supplied metadata and correct UUID filename.

Inspection hashes and scans files using bounded byte buffers and returns plain
source descriptors. Replay opens those sources instead of compacting buffers;
retained expected digests are checked against the resulting file bytes before
replacement integrity and completion records. Existing administrative copy
operations still buffer an individual file temporarily; this is outside the
retrieval/replay memory claim.

### Late read failures

DEF-20260923-TTZ7C-50 corrects a failure-classification gap introduced by lazy
reads. FileParser retains read/decode/reference failures in host-owned state.
Commands refuse publication even if a handler catches the error; query workers
report storage failure even if query code catches it. User-thrown error flags
cannot forge parser state. Runtime marks storage failure and refuses further
mutations, preserving ownership and administrative recovery evidence.

## Trusted unique ID indexes

The confirmed correction replaces routine header reconstruction with direct
committed ID-index loading. Missing indexes reconstruct; explicit validation
and reconstruction are available as store/loader options. Malformed present
indexes fail. Overlay application clears mappings for replaced records, then
adds unique IDs. Duplicate IDs are errors, not precedence cases.

The core prepares ID entries from final serialized bytes and checks uniqueness
before data publication. It awaits custom finalization, writes the ID sidecar
durably and returns matching live metadata. Conversion follows the same rules.
ID-only mutations are detected among materialized records before/after hooks.
Expected digests captured before finalizers prevent later canonical changes
from leaving successful publication with stale indexes. No legacy index path,
new index format or od-jsontag revision is needed.

Tests cover normal loading with tag parsing forbidden, ID-only edits without
reading untouched records, renames, removals, swaps, duplicate rejection before
publication, custom-hook final IDs, index-write failure, runtime/restart
agreement, conversion, and explicit maintenance.

Final review checks both the published file and the mutable serialization buffer
against the digest captured before custom finalization. Otherwise a finalizer
could change only the buffer and cause a later integrity entry to hash bytes
different from the published file. Two regression cases cover buffer-only and
buffer-plus-file mutation; the former reproduced the gap before correction.

## Direct offset loading and artifact hashes

The offset correction shares loadDataSource across startup inspection, loading,
command publication and recovery. Present offsets are checked for structural
ranges/bounds, then used directly. Only missing offsets or explicit maintenance
reconstruct framing. Missing IDs use stored ranges to read record headers.
Malformed present indexes fail; rebuild ignores them without changing disk.

index-files.mjs hashes the exact index bytes parsed against the existing manifest.
When integrity is enabled, conversion, commands and recovery append final ID and
offset hashes before success/done. Present indexes need hashes; missing files
can reconstruct from verified canonical data. Canonical hashing and file identity
checks remain bounded and independent of index reconstruction.

Regression coverage includes bypassing framing in both loader and inspection,
structurally valid content trust, malformed bounds, explicit rebuild, hash
mismatches/missing entries, conversion hashes, committed/no-op sidecars through
runtime reopen, and recovery of a fingerprinted prefix.
