# Implementation: Store Runtime And Express Shell

Implements DES-20260919-TTZ7C-32 by introducing `StoreRuntime` as the owner of an
opened store's state and lifecycle. It transforms the server/worker portion of
IMP-20260919-TTZ7C-26 without changing the accepted durability and recovery
semantics implemented there.

`src/store-runtime.mjs` now owns normalized store configuration, ownership,
startup inspection and loading, dataset buffers and metadata, command status and
queue state, query pools, storage failure and closing state. Its coordinating
methods describe opening, accepting, executing, publishing and closing in domain
order. Repeated status persistence is one named operation; lower-level append,
sync, fault, worker and pool mechanisms are supplied through one closed mechanism
object with concrete production defaults.

Command acceptance remains serialized through log append, accepted status and
queue insertion. The queue runs one command at a time in command-log order.
Active persistence precedes worker execution; required-file synchronization and
done persistence precede query publication. Safe handler failures receive their
terminal status, while storage uncertainty closes mutation and retains ownership.

`src/server.mjs` retains the package's default Express application plus `run()`
contract. It now owns only route/content negotiation, HTTP translation, static
resources, the listening socket, signals, logging and process exit. Command
handlers pass raw command text to the runtime, send its plain result and then
start queue draining, retaining the previous response/execution boundary.

`src/execute-worker.mjs` exposes the common one-shot worker protocol through
`runWorker`. Load timeout remains a rejected startup error. The existing
`executeWorker` command adapter converts that same timeout into the established
`unsafe` command result, preserving administrator assessment behavior. Query
workers remain in their long-lived pool abstraction.

`test/store-runtime.mjs` directly covers open/close ownership, durable acceptance,
duplicate IDs, delayed concurrent acceptance and execution order, terminal
handler failure, query publication and storage-failure admission closure using a
real temporary store plus narrow worker/query doubles. Existing process suites
remain the evidence for actual HTTP, workers, crashes and durable I/O.

No file format, migration, endpoint, command input, recovery policy, generic
container or framework is introduced.
